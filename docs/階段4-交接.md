# 階段 4（介面與橋接層）交接

> 日期：2026-11-15
> 用途：規劃階段 4 用。後端做到哪裡、橋接層要接什麼、有哪些事留到階段 4、開始前要先決定什麼。
> 依據：`介面與後端的約定.md`（下面簡稱「約定」）、`backend/app/composition.py`、`階段3-驗收.md`

## 摘要

- 後端的全部服務從 `app.composition.build(emit, data_dir, local_dir)` 拿，回傳的 `Backend` 有六個服務。橋接層只要做「轉接」。
- 約定的 24 個指令都對得到服務的方法（第 1 節）。對不上的只有形狀：服務用 Python 的資料類別與 `snake_case`，約定是小駝峰的 JSON。
- 5 種事件都經過 `emit` 送出，但來自不同的執行緒；橋接層要自己排隊再送給介面（第 2、3 節）。
- 留給階段 4 的事項共 31 項（第 4 節），開始前要作者先決定的有 8 項（第 5 節）。

## 2. 事件表

| 事件 | 誰送出 | 服務裡的型別 | 在哪條執行緒 | 那時拿著什麼鎖 |
|---|---|---|---|---|
| `tasksChanged` | `QueueService` | `TasksChanged(tasks)` | 佇列自己的送事件執行緒 | 沒有 |
| `tasksRemoved` | `QueueService` | `TasksRemoved(ids)` | 同上 | 沒有 |
| `taskProgress` | `QueueService` | `TaskProgress(id, progress)` | 同上 | 沒有 |
| `historyAdded` | `HistoryService.record()` | `HistoryAdded(entry)` | 剛完成的那個下載的執行緒（同時完成幾個就有幾條） | 沒有 |
| `settingsChanged` | `SettingsService`，經過 `composition.py` 的 `settings_changed()`（先通知佇列，再 `emit`） | `SettingsChanged(settings)` | 造成改變的那條執行緒：`update_settings`、`choose_download_folder`、`add_to_queue` 的呼叫者（也就是橋接層處理指令的執行緒） | **設定的寫入鎖** |

- 佇列的三種事件之間保證照順序；它們跟 `historyAdded`、`settingsChanged` 之間沒有順序保證。例如任務的 `done` 和它的 `historyAdded` 誰先到不一定。
- `historyAdded` 在抓完縮圖之後才送，比 `done` 晚 0.1–0.3 秒是正常的。
- `emit` 丟例外不會影響下載：三個服務都接住並寫進記錄檔。

## 3. 橋接層要處理的事

### 3.1 回覆的外形

每個指令回 `{ok: true, data}` 或 `{ok: false, error}`（約定 1.1）。例外的對應：

| 服務丟出的 | 回覆 |
|---|---|
| `EngineError` | `{ok: false, error: <它的 code>}` |
| `ValueError`、`TypeError`、`KeyError`（參數不合規定） | `{ok: false, error: "unknown"}`，原因寫進記錄檔 |
| 其他任何例外 | 同上。橋接層的每個方法都要包起來：例外漏給 pywebview 的話，介面那端的 Promise 會拿到一段英文錯誤訊息 |

記錄用 `logging`（已經由 `build()` 設定好，會遮個人路徑）；不要自己寫檔。

### 3.2 欄位名稱與形狀

- 資料類別的欄位是 `snake_case`，約定是小駝峰：`duration_sec → durationSec`、`size_bytes → sizeBytes`、`finished_at → finishedAt`、`download_dir → downloadDir`、`max_concurrent → maxConcurrent`、`on_duplicate → onDuplicate`、`mp3_bitrate → mp3Bitrate`、`mp4_height → mp4Height`、`current_version → currentVersion`、`latest_version → latestVersion`、`app_version → appVersion`、`done_bytes → doneBytes`、`total_bytes → totalBytes`、`speed_bps → speedBps`、`eta_sec → etaSec`。
- **沒有值的欄位不出現**（約定 1.2）：值是 `None` 的鍵整個拿掉，不要送 `null`。
- `QueueItem.skipped` 是布林：`False` 時不出現，`True` 才送。
- `QueueItem.progress` 是巢狀的 `Progress` 或 `None`：要攤平成 `percent`、`doneBytes`、`totalBytes`、`speedBps`、`etaSec` 放在項目上；`None` 時這五個都不出現。
- `TaskProgress` 事件同樣攤平：`{type: "taskProgress", progress: {id, percent, …}}`。
- `speed_bps` 是浮點數，約定只說是數字；建議四捨五入成整數。
- 列舉（`Format`、`TaskStatus`、`ErrorCode`、`OnDuplicate`、`Language`、`Opened`）都是 `StrEnum`，值就是約定的字串，轉 JSON 時不用另外對照。
- tuple 轉成清單。
- 事件要加 `type`：`tasksChanged`（`tasks`）、`tasksRemoved`（`ids`）、`taskProgress`（`progress`）、`historyAdded`（`entry`）、`settingsChanged`（`settings`）。
- 成品路徑不在任何給介面的資料裡（`QueueItem`、`HistoryEntry` 本來就沒有），不要自己加。唯一的路徑是 `Settings.download_dir`。

### 3.3 事件為什麼要自己排隊再送

`emit` 被呼叫時：

1. `settingsChanged` 還拿著設定的寫入鎖。`emit` 卡住，所有改設定的指令和 `add_to_queue`（要記住格式）都會卡住。
2. `historyAdded` 在下載的執行緒上。`emit` 卡住，那個下載的空位就不會讓出來。
3. 佇列的事件在佇列的送事件執行緒上。`emit` 卡住，之後所有佇列事件都排在後面。
4. 把事件送進網頁（pywebview 的 `evaluate_js`）要等介面那條執行緒，可能慢，視窗還沒準備好或正在關閉時還會失敗。

所以橋接層的 `emit` 只做一件事：把事件放進自己的佇列（`queue.SimpleQueue`）就返回。另外一條 daemon 執行緒把事件取出來、轉成 JSON、送進網頁。這樣也順便讓三個來源的事件在同一條執行緒上依序送出。

`emit` 裡不可以呼叫任何服務（尤其不可以改設定：會死結）。

### 3.4 啟動與關閉

啟動：

1. `backend = build(emit)`（不傳資料夾就是正式的位置；開發時資料夾名稱是 `media-downloader-dev`）。
2. `backend.start()`：清掉下載資料夾裡上次留下的 `.md-tmp-*`。要在任何 `add_to_queue` 之前呼叫，只呼叫一次。
3. 建立視窗，把橋接層的物件交給 pywebview。
4. 介面準備好之後自己叫 `get_queue`（啟動時一定是空的）、`get_settings`、`check_app_update`。

關閉：

1. 視窗關閉時呼叫 `backend.shutdown()`：停止全部下載、最多等 5 秒讓暫存資料夾刪完。實測有下載在跑時 0.02 秒返回。
2. `shutdown()` 之後 `add()` 回空清單，其他指令不會有動作。
3. 就算沒呼叫到 `shutdown()`（App 當掉、被強制結束），下載程序也會跟著結束（Job Object），暫存資料夾下次啟動時清掉。

### 3.5 選擇下載資料夾的視窗

- 視窗由橋接層開（pywebview 的資料夾對話框），因為它需要視窗物件；服務層不知道 pywebview。
- 選到的路徑直接交給 `backend.settings.set_download_dir(path)`，不經過介面。
- 服務會檢查：絕對路徑、資料夾存在、可以寫入；不符合丟 `ValueError`。
- 換資料夾不影響已經在佇列裡的任務。

### 3.6 執行緒

- pywebview 每個來自介面的呼叫各用一條執行緒，所以 `lookup`、`update_engine` 卡住不會擋到其他指令。服務都可以被多條執行緒同時呼叫。
- 同一個網址同時 `lookup` 兩次只會查一次，兩邊拿到同一個結果。
- 橋接層不放業務邏輯（`CLAUDE.md` 依賴規則 5），也不 import `infrastructure/`（`test_layering.py` 會檢查）。組裝在 `composition.py`，由 `main.py` 呼叫。

## 5. 階段 4 開始前要作者先決定的事

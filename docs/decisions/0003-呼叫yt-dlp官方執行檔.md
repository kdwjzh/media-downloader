# 0003. 呼叫 yt-dlp 官方執行檔

- 日期：2026-11-11
- 狀態：已採用

## 背景

舊專案把 yt-dlp 當 Python 函式庫使用，有三個問題：yt-dlp 不會自己更新，YouTube 一改版就壞；取消下載只改了旗標，實際上還在跑；單一下載出錯可能影響整個程式。

另外，yt-dlp 從 2025.11.12 版起，完整支援 YouTube 需要外部 JavaScript 執行環境（官方建議 Deno）與 yt-dlp-ejs 元件，官方執行檔已內含 yt-dlp-ejs（yt-dlp/yt-dlp#15012）。

## 決定

把 yt-dlp 官方執行檔當成獨立程式呼叫，不 `import yt_dlp`。隨 App 附帶 yt-dlp、Deno、FFmpeg（含 ffprobe；技術驗證後改為不附 ffprobe，見 `docs/技術驗證.md` 的 D6）。

## 理由

- yt-dlp 可以用它自己的更新指令更新，跟 App 版本無關，使用者不用等新版 App。
- 取消下載就是結束那個程序。
- 一個下載當掉不會拖垮整個 App。
- 官方執行檔已內含 yt-dlp-ejs，不用自己對版本。

## 考慮過的其他做法

- 當函式庫打包進 App：進度資訊直接是 Python 資料，比較好拿；但每次 yt-dlp 更新都要重新打包發版，取消與暫存檔清理也要自己處理。

## 後果

- 進度要用 yt-dlp 的進度樣板輸出 JSON 再解析。
- 安裝檔會因為附帶外部程式而變大，確切大小待技術驗證階段實測。
- yt-dlp 要能自我更新，所在資料夾必須讓一般使用者可寫入。外部程式放哪裡（安裝到使用者資料夾，或首次啟動時複製出去）待技術驗證後另立一份決策紀錄（已定案，見 0005；2026-11-19 由 0018 取代）。
- 只有 `infrastructure/engines/ytdlp/` 可以知道 yt-dlp 的細節。

# 0013. 主畫面的狀態管理與行為

- 日期：2026-11-16
- 狀態：已採用

## 背景

階段 4b 把主畫面接上真的後端。要決定：介面的狀態放哪裡、事件與 `get_queue` 的先後怎麼對、
晚到的查詢結果怎麼丟、畫面壞掉時怎麼還能關窗，以及第一步設計時作者定的 9 項（D1–D9）。

## 決定

1. **狀態放 Zustand 的 store**（`frontend/src/stores/`）：`queue`、`preview`、`settings`、`notices`（toast 與朗讀）、`start`。
   元件透過 stores 做事，stores 透過 `api/` 叫後端。`start()` 在 `main.tsx`、React 外面呼叫：先訂閱事件，再叫 `getQueue` 與 `getSettings`。
2. **佇列以事件為準**：`tasksChanged` 的項目整個換掉（位置不動，新的加在最下面）；`taskProgress` 把五個進度欄位整組換掉，只套在 `downloading` 的項目上。
   `getQueue` 回來之前事件已經講過（或已經移除）的任務，以事件為準；其他的用回覆補上。
3. **預覽當下選的格式放在 store**：連續貼網址時要用它自動加入（`decisions/0006`）。
   使用者動過格式或畫質的預覽，`settingsChanged` 不覆蓋；沒動過的跟著換。
4. **晚到的 `lookup` 結果靠編號丟掉**：每次查詢拿一個編號，關閉預覽、新的查詢、加入佇列都讓編號前進，回覆的編號不是現在的就丟掉。後端不中止查詢（約定 Q5）。
5. **錯誤邊界兩層**：主內容區一層、整個 App 一層。關閉確認在主內容區那層外面，並且由它自己訂閱 `onCloseRequested`。
   它也壞掉時就不再訂閱，`api/` 沒有人訂閱時直接 `confirm_close`（`decisions/0012`），所以視窗一定關得掉。
   收到 `closeRequested` 時如果已經沒有沒結束的任務，直接關，不問。
6. **作者在第一步定的 9 項**（2026-11-16，全部照建議）：
   - D1 關閉確認的「不關」叫「繼續下載」，不叫「取消」。
   - D2 剛輪到、還沒有任何進度（`doneBytes` 是 0 且沒有 `totalBytes`）時顯示「準備下載…」加不確定進度條。
   - D3 新增 toast 元件（規格在 MASTER）。
   - D4 錯誤邊界兩層。
   - D5 焦點在空的網址框按 Ctrl+V 也立刻查詢。
   - D6 貼的不像網址時介面先擋，顯示 toast。
   - D7 `settingsChanged` 不覆蓋使用者動過的預覽。
   - D8 新增 `zustand`，開發用 `@testing-library/react`、`@testing-library/dom`、`jsdom`。
   - D9 英文的 `unknown` 提示縮短，720 寬放得下。
7. **最小視窗維持 720x520**（第三步，作者決定）：理由寫在 `decisions/0006` 的後果。

## 理由

- 狀態在 React 外面，畫面壞掉重新載入也不影響收事件；store 也能不開視窗直接測。
- 回覆與事件沒有共同的順序編號，誰比較新沒辦法判斷。啟動時佇列通常是空的，只有「重新載入畫面」才會碰到；
  選「事件為準」是因為事件一定是某個時間點的完整項目，而且之後的事件還會繼續修正。
- 介面先擋不像網址的內容：不擋的話，誤貼一段文字會觸發「把上一個預覽自動加入佇列」。
- 關閉確認的訂閱留在元件裡（不放 store），才能用「元件不見 = 沒有人訂閱 = 直接關」這條既有的路。

## 代價

- 「重新載入畫面」時，如果某個任務的事件比 `get_queue` 的回覆舊，那一列會顯示舊的狀態，直到它下一次改變。已經結束的任務不會再有事件，可能一直停在舊狀態。
- 介面的錯誤只進瀏覽器主控台，不進後端的記錄檔（要的話得加指令）。
- 自動加入「還在查詢中」的網址如果被後端拒絕（`invalidUrl`），不會有任何提示，那個網址就沒了。
- 確認視窗與 toast 沒有淡出（內建 `<dialog>` 關閉時立刻消失）。
- 元件測試裡的 `<dialog>` 是自己補的 `showModal()`，焦點鎖定與 Esc 只在真的視窗裡才驗得到。
- 縮圖由 WebView2 直接向 YouTube 載入，不經過 `infrastructure/http.py`（那條規則管的是後端自己連網路）。

## 沒採用的做法

- 狀態放 React 的 context：要包在元件樹裡，畫面壞掉時跟著不見。
- 先把事件暫存起來，等 `get_queue` 回來再重播：會把已經完成的任務倒回下載中。
- 關閉確認的訂閱放在 store：畫面壞掉時 store 還在訂閱，但沒有人顯示視窗，視窗就關不掉了。

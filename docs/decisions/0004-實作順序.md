# 0004. 實作順序：先技術驗證，再 UI 設計，再後端

- 日期：2026-11-11
- 狀態：已採用

## 背景

這個專案同時要把後端做穩，以及練習 UI 設計流程。兩者誰先做會影響返工的多寡。

## 決定

依序進行：

0. 骨架：目錄、一鍵檢查、CI，開出空白視窗。
1. 技術驗證：只確認 yt-dlp 執行檔的實際行為與回傳資料，結果寫進 `docs/技術驗證.md`。不寫正式後端。
2. UI 設計：以階段 1 的真實資料為依據，產出設計規範。
3. 後端完整實作。
4. 介面實作、接上後端、雙語。
5. 打包與發佈。

## 理由

- 設計畫面時手上有真實資料（有哪些欄位、哪幾種錯誤、進度分幾個階段），不會設計出後端做不到的畫面。
- UI 設計是作者投入最多、也最想練的部分，不必等後端全部完成。
- 最不確定的技術（yt-dlp 執行檔、Deno、進度解析、取消）最先處理。

## 考慮過的其他做法

- 先做完整後端：風險最低，但很長一段時間沒有畫面，UI 練習被推到後面。
- 先做 UI 設計：最快開始練習，但設計可能假設了拿不到的資料（例如不是每支影片都有檔案大小、轉檔階段沒有精確百分比），之後要回頭改。

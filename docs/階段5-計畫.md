# 階段 5（打包與發佈）計畫

> 日期：2026-11-19
> 狀態：已確認（第 1 節的決定作者於 2026-11-18～19 確認）
> 依據：`階段5-交接.md`、`階段4-驗收.md`；發佈方式的比較在 claude.ai 專案的「發佈方式比較」文件

## 摘要

- 發佈方式：**Inno Setup 安裝檔，加上 App 內的一鍵自動更新**。不做免安裝的單一 exe。
- 外部程式（yt-dlp、FFmpeg、Deno）改放在共用資料夾 `%LOCALAPPDATA%\media-downloader\bin`，不放安裝資料夾。取代 `decisions/0005` 的做法。
- App 啟動時自動檢查並更新 yt-dlp（新增，原本只能手動）。
- 分五段（5a–5e），一段一個工作階段。
- 第一個公開版本是 `1.0.0`；公開前私下測試的版本標 `1.0.0-rc.N`。之後發 `1.0.1` 驗證自動更新。

## 1. 已決定的事

### 1.1 發佈方式（2026-11-19）

| 事項 | 決定 | 理由 |
|---|---|---|
| 形式 | Inno Setup 安裝檔，「僅目前使用者」安裝到 `%LOCALAPPDATA%\Programs`，不需要系統管理員權限 | 打包最成熟、不需網路就能第一次使用、開啟快、防毒誤判風險低；放檔案、換檔案、刪檔案都交給 Inno Setup，App 要改的程式最少 |
| 不做的 | 免安裝的單一 exe | 要多做第一次開啟的下載畫面、自己換掉自己的更新、清除資料；而且開啟速度與防毒誤判要打包後才知道。作者原本偏好它，比較後選了安裝檔版 |
| 外部程式位置 | `%LOCALAPPDATA%\media-downloader\bin`（開發時仍用 repo 的 `bin/`） | App 更新（重跑安裝程式）不碰這個資料夾，使用者更新過的 yt-dlp 不會被蓋回舊版；使用者把 App 裝在哪都不影響 yt-dlp 更新 |
| App 更新 | 有新版時設定頁顯示「立即更新」：App 下載新的安裝檔、核對檢查碼、在背景執行、關閉 App，裝完重新開啟。由使用者按下才開始，不自動進行 | 自動重開會打斷正在進行的下載 |
| yt-dlp 更新 | App 啟動時自動檢查（例如一天一次），有新版就在背景更新；設定頁的手動按鈕保留 | yt-dlp 過時是這類工具最常壞掉的原因；安裝檔附的 yt-dlp 在發版後會漸漸過時 |
| 下載時的轉址 | `infrastructure/http.py` 改成「只允許轉到允許清單上的網址」 | GitHub 發佈檔的下載一定會轉址；目前一律不跟隨轉址，自動更新會下載不了 |

## 2. 分段

| 段 | 內容 | 驗收 |
|---|---|---|
| 5a 安裝檔 | 外部程式改放共用資料夾（`binaries/`、決策紀錄取代 0005）；FFmpeg 固定版本、不附 ffprobe；PyInstaller 資料夾模式；Inno Setup 腳本（僅目前使用者、開始功能表、解除安裝時詢問、不覆蓋已存在的 yt-dlp）；沒有 WebView2 時的處理；Windows Defender 掃描 | 在作者的電腦與 Windows Sandbox 安裝、下載、解除安裝；U2（沒有主控台視窗）、U4（沒有 Python 的電腦能用）；打包後的路徑、Job Object、資料夾名稱 |
| 5b 自動更新 | 啟動時自動更新 yt-dlp；App 的「立即更新」（下載安裝檔、核對、背景執行、重新開啟）；`http.py` 的轉址允許清單；約定與畫面（先設計再做）；不經 GitHub 也能測更新的方式（只在開發用，不能進正式版） | 用兩個本機建置的版本，從舊版一鍵更新到新版；yt-dlp 啟動時自動更新 |
| 5c CI 與檢查 | GitHub Actions 打包安裝檔與檢查碼；gitleaks 加進 CI 掃整個歷史；三個版本號一致的檢查；私下打出 `1.0.0-rc.N`（不發佈） | 下載 Actions 打出來的安裝檔，在 Sandbox 測一次；gitleaks 的掃描結果 |
| 5d 公開前準備 | 照翻譯範圍翻成英文；README 的安裝、更新、常見問題（含 SmartScreen）、第三方元件與授權（含兩個字體與 FFmpeg 的 GPL）；搜尋個人資料；依 5c 的掃描結果決定歷史怎麼處理 | 作者看過 README 與掃描結果 |
| 5e 公開與發佈 | repo 公開；發 `1.0.0`；發版後驗證（檔案齊全、檢查碼、下載、安裝、新版圓點）；發 `1.0.1` 驗證自動更新 | 從 1.0.0 一鍵更新到 1.0.1；新版圓點與「立即更新」在真的 GitHub 發佈上運作 |

## 3. 要注意的事

- 開發模式（`--dev`、沒有打包）的行為不能改變：外部程式仍從 repo 的 `bin/` 拿，資料夾名稱仍帶 `-dev`。
- 自動更新會讓 App 自己下載並執行程式：下載位址寫死在後端、只允許 https 與允許清單上的主機、一定核對檢查碼，核對失敗就不執行。
- 解除安裝與更新時 App 可能還開著，或還有下載在進行：要處理。
- 交接文件第 2 節的 30 項，逐項標出在哪一段處理或決定不處理。
- 新版檢查目前「看不懂的版本號當成沒有新版」：`1.0.0-rc.N` 這種版本號的行為要確認，私下測試時不能誤判。

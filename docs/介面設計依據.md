# 介面設計依據（階段 2 用）

> 日期：2026-11-12
> 用途：設計畫面時，哪些資料拿得到、哪些拿不到、每個狀態能顯示什麼。
> 來源：`技術驗證.md`（階段 1 的實測結果）與 `功能規格.md`。這份只整理跟介面有關的部分，數字與細節以 `技術驗證.md` 為準。

## 摘要

- 貼上網址後要等 3–4 秒才有影片資訊，這段時間後端沒有任何輸出，畫面要自己顯示「查詢中」。
- 只有「下載」階段有真實百分比。轉檔、嵌入封面、合併只有開始與結束，不能畫出百分比。
- 檔案大小只能顯示「約」；MP3 的大小是估算的，播放列表的項目完全沒有大小。
- 畫質選項可以做成「上限」（最高到 1080p），影片沒那麼高時會自動拿現有最高畫質，所以不用等查完資訊才能選。
- 第一版沒有登入功能，年齡限制、私人、會員限定的影片一律下載不了，錯誤訊息不要叫使用者去登入。

## 0. 已決定的操作方式（2026-11-12）

| 項目 | 決定 |
|---|---|
| 貼上網址後 | 先顯示預覽（縮圖、標題、頻道、時長），使用者確認格式與畫質後按「加入佇列」才加入。不是貼上就直接下載 |
| 預覽的預設值 | 格式與畫質帶入上次用的設定，不想改的人可以直接按加入 |
| 加入佇列後 | 自動開始，受同時下載數限制，超過的排隊 |
| 播放列表 | 貼上後顯示勾選清單，整批用同一組格式與畫質（畫質是上限），確認後一次加入佇列 |
| 視窗 | 一般視窗，預設 960x680，可調整大小，不在啟動時最大化。設計要定出最小尺寸 |
| 同時下載數 | 預設 3，設定頁可調 1–3。4、5 還沒實測；階段 3 實測沒問題就正式改成 1–5。設定頁的設計要讓這個範圍之後能直接改，不必重排版面 |
| 視覺方向 | 「唱片封套」（2026-11-13 選定），規範在 `design-system/media-downloader/MASTER.md` |
| 視窗最小尺寸 | 720x520（2026-11-13） |

預覽階段對設計的影響：

- 預覽要等 3–4 秒才有內容，這段時間要有查詢中的樣子；查詢失敗時錯誤就顯示在預覽的位置，不會進佇列。
- 因為已經查完資訊，預覽上可以列出這支影片「實際有的」畫質和預估大小（第 1、4 節）。
- 預覽還沒加入時，使用者又貼了另一個網址（2026-11-13 決定）：舊預覽已查到的，用當下選好的格式自動加入佇列；還在查詢中的也加入佇列，以「查詢資訊中」顯示；查詢失敗的直接換掉。所以連續貼網址時，查詢失敗的錯誤會出現在佇列裡，這是上一點「不會進佇列」的唯一例外。細節在 `design-system/media-downloader/pages/main.md`。

## 1. 每種內容拿得到的資料

### 單支影片（查詢約 3–4 秒）

| 資料 | 拿得到嗎 | 備註 |
|---|---|---|
| 標題 | 有 | 可能很長，也可能含表情符號、日韓文 |
| 頻道名稱 | 有 | |
| 時長 | 有（秒） | |
| 縮圖 | 有，多種尺寸 | 最大到 1280x720 |
| 來源平台 | 有 | 第一版只會是 YouTube，欄位先留著 |
| 這支影片實際有哪些畫質 | 有 | 直式影片要用短邊當畫質（1080x1920 算 1080p） |
| 預估檔案大小 | 部分 | MP4：多數情況可由影像＋聲音相加得到；MP3：只能用位元率乘時長估算。一律標「約」，也要能處理「不知道」 |
| 是否直播、是否年齡限制 | 有 | 直播不在第一版範圍，查到時要有說明 |

### 播放列表（100 支約 3 秒）

| 資料 | 拿得到嗎 | 備註 |
|---|---|---|
| 列表標題、頻道、總數 | 有 | |
| 每個項目的標題、時長、頻道 | 有 | 實測 99 支都齊全 |
| 每個項目的縮圖 | 有，但只有小圖 | 最大 336x188，清單裡不要放大顯示 |
| 每個項目的可用畫質、檔案大小 | 沒有 | 要逐支查才有（每支 3–4 秒），勾選清單上不要設計這兩欄 |
| 項目是否私人或已刪除 | 不確定 | 這次沒遇到，設計時要留一種「無法下載的項目」樣式 |

超過 200 支的列表還沒測過，清單要能捲動並考慮效能。

## 2. 佇列項目的狀態與可顯示的內容

| 狀態 | 持續多久 | 能顯示什麼 | 不能顯示什麼 |
|---|---|---|---|
| 排隊中 | 視前面的任務而定 | 標題等資訊（若已查到）、「等待中」 | |
| 查詢資訊中 | 約 3–4 秒 | 網址、不確定進度的動畫 | 標題、縮圖、百分比（都還沒有） |
| 下載中 | 視檔案大小 | 真實百分比、已下載／總大小、速度、剩餘時間 | |
| 下載中（MP4） | 同上 | 影像與聲音合成一條進度，不要讓進度條跑兩次 | |
| 連線中斷重試中 | 最長可達數十秒 | 「連線中斷，重試中（第幾次）」 | |
| 轉檔中（MP3） | 短片不到 1 秒，1 小時的音訊可能幾十秒 | 階段名稱＋不確定進度 | 百分比 |
| 嵌入封面中 | 不到 1 秒 | 階段名稱，或併入上一個階段 | 百分比 |
| 合併中（MP4） | 通常不到 1 秒 | 階段名稱，或直接略過不顯示 | 百分比 |
| 完成 | | 成品的確切路徑（可做「開啟資料夾」）、最終檔案大小 | |
| 失敗 | | 錯誤類別對應的說明與下一步（見第 3 節） | |
| 已取消 | 取消約 0.4 秒內生效 | 可重新加入佇列 | |

設計時要注意：

- 進度條要有「確定」與「不確定」兩種樣式，而且從下載切到轉檔時，不能讓使用者覺得卡在 100%。
- 短片的後處理階段一閃而過，階段文字不要造成畫面跳動。
- 同時下載數預設 3（實測沒有問題），上限先定 3。

## 3. 錯誤類別

第一版沒有登入（cookies）功能。標「不行」的重試了也沒用，不要放重試按鈕。

| 錯誤 | 使用者看到的情況 | 重試有用嗎 | 說明方向 |
|---|---|---|---|
| 網址無效 | 貼的不是網址，或網址不完整 | 不行 | 請確認網址 |
| 不支援的網站 | 不是支援的平台 | 不行 | 說明目前支援哪些 |
| 影片不存在或已移除 | | 不行 | 影片已不存在 |
| 私人影片 | | 不行 | 這是私人影片，目前無法下載 |
| 年齡限制 | 需要登入確認年齡 | 不行 | 目前不支援需要登入的影片 |
| 會員限定 | 訊息樣本還沒取得 | 不行 | 同上 |
| 地區限制 | 你的地區無法觀看 | 不行 | 這支影片在你的地區無法觀看 |
| 播放列表不存在 | | 不行 | |
| 網路問題 | 一開始連不上，或下載到一半斷線 | 可以 | 請檢查網路後重試 |
| 未知錯誤 | 分類不出來 | 可以試 | 提供「開啟記錄檔」 |

網路問題從發生到確定失敗可能要 10–40 秒（yt-dlp 會先自動重試），這段時間對應第 2 節的「連線中斷重試中」。

## 4. 畫質與格式選項

- MP4 的畫質選項是「上限」：選 1080p 表示「最高到 1080p」，影片沒那麼高就拿現有最高的。所以選項不必等查完資訊才出現，也可以直接套用到整個播放列表。
- 查到資訊後可以知道這支影片實際最高到多少，介面可以據此標示或停用超過的選項。
- 4K 的成品是 VP9 編碼裝在 mp4 裡，部分播放器可能無法播放。要不要在選 4K 時提示，設計時決定。
- MP3 的音質選項是轉檔的位元率（例如 128／192／320 kbps），跟影片本身無關，隨時可選。

## 5. 不要設計的東西

| 項目 | 原因 |
|---|---|
| 轉檔、合併的百分比 | 資料不存在 |
| 播放列表項目的檔案大小、可用畫質 | 要逐支查才有 |
| 「登入後下載」的入口或提示 | 第一版沒有登入功能 |
| 精確到位元組的預估大小 | 只有估計值，有時連估計值都沒有 |
| 彈出視窗式的更新通知 | 舊版的問題 U1；改成介面內的一條提示 |

## 6. 做假資料時可以用的樣本

設計與做畫面時用這些真實情況，不要只用短短的英文標題：

| 情況 | 樣本 |
|---|---|
| 長的中文標題、全形標點 | 公視新創電影《最後的詩句》30秒搶先看！（頻道：公視戲劇 PTS Drama，42 秒，最高 1080p） |
| 很短的影片、低畫質 | Me at the zoo（19 秒，4:3，最高 240p） |
| 英文長標題 | 4K 2K 1080p 720p 480p video resolution test（11 秒，最高 2160p） |
| 音樂類、含歌手名 | Shakira, Burna Boy - Dai Dai (Official Video)（4 分 1 秒） |
| 長時間音訊 | White Noise 1 Hour Long（1 小時，轉檔階段會持續一陣子） |
| 大檔案 | 5 分鐘的 4K 影片，約 966 MB |
| 播放列表 | Top 100 Songs Global，99 支 |
| 直式影片 | 1080x1920，51 秒 |

## 7. 還不確定、設計時要留彈性的地方

- 會員限定影片的訊息還沒取得樣本。
- 超過 200 支的播放列表、含私人或已刪除項目的列表。
- 真的斷網時的訊息（這次用模擬的）。
- 英文系統下的顯示。

## 摘要

- 階段 4 把階段 2 的樣張接上階段 3 的後端，並做出另外三個畫面。
- 分六段（4a–4f），每段各自驗收，一段一個工作階段。
- 4b 結束時 App 第一次可以真的拿來下載。
- 4c–4e 的三個畫面只有規範與線框圖，沒有樣張：每個畫面做出來先給作者看，再接後端。
- 這個階段結束時，`功能規格.md` 3.1 的每一項、舊版問題中屬於介面的項目都要驗過。

## 3. 每段要注意的事

### 共通

- UI 工作流程照 `CLAUDE.md`：先讀 `MASTER.md` 與對應的 `pages/`，用 ui-ux-pro-max 查規則，視覺決定依 frontend-design。
- 顯示給使用者的文字都進語言檔，中英文一起加。
- 介面只有 `frontend/src/api/` 可以呼叫橋接層。
- 元件要能用假的 `api` 測試，不必開視窗。

### 4a

- 橋接層只做轉接，不放業務邏輯，不 import `infrastructure/`。組裝在 `composition.py`，由 `main.py` 呼叫。
- 任何例外都不能漏給介面：每個指令都要包起來。
- 事件要自己排隊再送，原因見交接文件 3.3。視窗還沒準備好、正在關閉時的事件要處理。
- 轉換規則要有測試：小駝峰、沒有值的欄位不出現、進度攤平、`skipped` 為否時不出現。
- 介面在瀏覽器分頁開啟時沒有後端：`api/` 要有清楚的行為（不是整個畫面壞掉），樣張與元件測試才能繼續用。
- 403 重試在引擎裡；要有錄下來的真實 403 訊息當測試樣本。

### 4b

- 佇列的畫面只靠事件更新，啟動時叫一次 `get_queue`。
- 進度可能沒有百分比、可能停在 97–99% 就換階段、輪到後有 4–5 秒是 0%：這些都是正常情況，畫面要自然。
- 連續貼網址的三種情況由介面判斷（`decisions/0006`）。
- 關掉查詢中的預覽後，晚到的結果要丟掉。
- 最小視窗尺寸的問題在這一段看到真的畫面後決定。

### 4c

- 清單沒有檔案大小與可用畫質兩欄。
- 無法下載的項目只有網址、沒有標題。
- 1,700 支的列表查詢要 11 秒、資料 2.3 MB：等待中的樣子要撐得住這個時間。

### 4d

- 縮圖是後端給的圖片內容，直接當圖片來源用。
- 時間依介面語言的格式顯示成當地時間。
- 紀錄多到幾百筆時的載入速度先量一次，變慢再處理。

### 4e

- 改了就生效，沒有儲存按鈕。
- 「預設格式」與預覽區塊「記住上次用的」是同一組值，兩邊要同步。
- 更新 yt-dlp 可能要二十秒，這段時間按鈕的狀態要清楚。
- repo 還是私人時查不到新版，畫面當成沒有新版。

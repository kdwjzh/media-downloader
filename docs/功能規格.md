## 摘要

- **定位**：以抓音樂為主、影片為輔的 Windows 桌面下載器，自己用也給別人用。
- **核心改變**：用「下載佇列」取代「一次一支 + 獨立播放列表視窗」。
- **技術方向**：Python 後端 + React 網頁介面，用 pywebview 包成桌面視窗，下載交給 yt-dlp 官方執行檔。
- **發佈方式**：GitHub Releases 提供安裝檔，不再是「下載 zip + 跑 bat」。
- **語言**：介面與 README 都是繁體中文、英文雙語。
- **未來**：先做 YouTube，架構預留其他平台（TikTok、Instagram、X、Telegram 等）。
- **拿掉**：格式轉換器、圖片教學視窗、xcopy 式自動更新。

## 2. 舊版問題清單（驗收時逐項確認已解決）

### 2.1 使用者實際遇到的

| # | 症狀 | 原因（舊程式碼位置） | 新版做法 |
|---|---|---|---|
| U1 | 開啟後更新通知按確定又跳一次 | 啟動時 `check_update()` 預設 `silent=False`。`UpdateChecker._check_update` 自己跳一次對話框，結果傳回 `MainWindow._on_update_checked` 又跳一次。repo 沒有 release，所以每次都是「無法連線」連跳兩次 | 啟動時靜默檢查，有新版才在介面內顯示一條提示，不用彈窗；顯示邏輯只放一處 |
| U2 | 桌面會出現 cmd 視窗 | 用 `run_app.bat` 啟動 `python.exe`（主控台程式） | 打包成視窗程式；呼叫外部程式時加上不顯示主控台的旗標 |
| U3 | 進度條不跟著 % 數跑 | (a) 進度從 yt-dlp 的 `_percent_str` 文字解析，文字帶顏色碼時解析失敗變 0；(b) MP4 是影像、聲音兩個檔分開下載，各自從 0 跑到 100；(c) 轉 MP3、合併階段沒有進度；(d) 下載開始時送了一筆沒有 percent 的狀態把進度歸零 | 用位元組數字計算；把「下載影像 → 下載聲音 → 轉檔/合併」算成一條總進度，並顯示目前階段。轉檔、合併階段 yt-dlp 不提供百分比，顯示階段名稱與不確定進度 |
| U4 | 只能下載整包 zip，再用 bat 安裝、啟動 | 沒有打包，也沒有發佈 release | GitHub Releases 提供安裝檔，安裝後從開始功能表啟動 |

### 2.2 從程式碼讀到的

| # | 問題 | 新版做法 |
|---|---|---|
| C1 | 畫質比對寫死「高度完全相等 + 只要 mp4」，非 16:9 影片常掉到 360p，2K/4K 多半拿不到 | 用 `-S res:N` 取最接近的畫質（以短邊計算，直式影片也正確），偏好 H.264 + AAC，最後合併成 mp4；4K 沒有 H.264，會是 VP9 |
| C2 | 背景執行緒直接改 UI，偶發卡住或閃退 | 下載核心只送事件，介面層接收後更新 |
| C3 | 取消只改旗標，yt-dlp 繼續跑 | 結束整棵程序樹；每個任務有自己的暫存資料夾，取消後整個刪掉 |
| C4 | 一次只能下載一個 | 佇列 + 可設定同時下載數 |
| C5 | 設定不會存檔 | 設定檔存在使用者資料夾 |
| C6 | yt-dlp 不會更新，YouTube 改版就壞 | yt-dlp 可獨立於 App 更新 |
| C7 | 轉檔用 moviepy，要鎖版本、附修復腳本 | 移除 moviepy，一律用 FFmpeg |
| C8 | 要使用者自己裝 FFmpeg | 隨程式附帶 |
| C9 | 貼網址重複抓資訊；`music.youtube.com`、`m.youtube.com` 被判無效 | 網址判斷交給 yt-dlp，不自己寫正規表示式 |
| C10 | 歷史紀錄用影片 ID 刪除，會刪錯筆 | 每筆紀錄有自己的唯一 ID |
| C11 | 只用 `print` 除錯 | 寫入 log 檔，介面提供「開啟記錄檔」 |

## 3. 功能範圍

### 3.1 第一版（MVP）

| 功能 | 說明 |
|---|---|
| 下載佇列 | 連續貼多個網址，每個項目獨立顯示進度、可取消、可重試；可設定同時下載數 |
| 播放列表 | 貼播放列表網址後展開成佇列項目，可勾選要下載哪些；不再是獨立視窗 |
| 格式 | MP3、MP4 |
| 畫質/音質 | 依該影片實際可用的選項列出，顯示預估檔案大小 |
| 影片資訊預覽 | 縮圖、標題、時長、頻道 |
| 嵌入縮圖 | 音樂檔封面 |
| 預設值 | 記住上次的格式、畫質、路徑；新加入佇列的項目套用預設，個別可改 |
| 歷史紀錄 | 重新下載、開啟所在資料夾、刪除單筆、清空 |
| 設定頁 | 下載路徑、預設格式與畫質、同時下載數、重複檔處理方式、介面語言、檢查更新、關於 |
| 重複檔處理 | 略過／覆蓋／自動改名 |
| 錯誤訊息 | 私人影片、年齡限制、會員限定、地區限制、網路中斷各自說明原因與下一步 |
| 介面語言 | 繁體中文、英文，可在設定頁切換，預設跟隨系統 |
| 更新 | yt-dlp 可獨立更新；App 本身有新版時在介面內提示 |
| 發佈 | GitHub Releases 提供 Windows 安裝檔；不需安裝 Python、不出現 cmd 視窗、內含 FFmpeg |
| 文件 | README 中英文各一份，檔案開頭互相連結 |

| 用瀏覽器 cookies 下載會員／年齡限制影片 | 也是支援 Instagram 等平台的前提 |

### 3.3 未來：其他平台

第一版只保證 YouTube。架構上預留，不在第一版測試與承諾。

| 平台 | 可行性 | 說明 |
|---|---|---|
| TikTok、Instagram、X、Facebook 等 | 沿用同一個下載引擎 | yt-dlp 本身支援；主要工作是登入 cookies、各平台的格式選項差異、介面上的平台標示 |
| Telegram | 需要另一套引擎 | 要用 Telegram 帳號登入並透過它的 API 取得檔案，機制與 yt-dlp 不同，獨立評估（此判斷尚未查證） |

對第一版的影響：
- App 名稱與程式內部命名不綁定「YouTube」。
- 佇列項目要有「來源平台」欄位。
- 下載引擎要有統一介面，之後才能加第二種引擎。

### 3.4 不做

| 項目 | 原因 |
|---|---|
| 格式轉換器 | 作者幾乎沒用，跟下載器核心無關，又是舊版安裝問題的來源 |
| 圖片教學說明視窗 | 介面本身要能看懂 |
| 選單列（文件／關於／檢查更新） | 併入設定頁 |
